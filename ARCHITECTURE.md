# geozarr-viewer: architecture

A Claude skill that assembles a **standalone GeoZarr viewer page** from a component library and a layout spec.
Starting point: `geozarr-pyramid-maker/src/geozarr_pyramid_maker/templates/preview.html` (called *the reference*
below). Components may drift from the reference; they only have to work and stay modular.

## Output contract

- One `.html` file, no build step needed to open it: pinned CDN imports (OpenLayers 10.10.0, proj4 2.22.0, zarrita
  0.7.3 = the instance OL's GeoZarr source uses, plus zarrita 0.7.5 loaded on demand by `browserConfig`, as in the
  reference), one `<style>`, one `<script type="module">`, one embedded
  `<script id="spec" type="application/json">` holding the *resolved* spec (defaults filled in, requires added).
  The page must be opened over http (`scripts/serve.py`), not from disk.
- The page loads the store **in the browser** (the reference's `browserConfig`/`openStore`, D-35, D-56): from
  `?store=…&endpoint=…`, else the spec's `store`/`endpoint`. No Python config path.
- Stores without CORS need a relay: the spec option `relay` (a URL prefix, e.g. `/proxy/`) is prepended to every
  store URL. `scripts/serve.py` provides it for local use.

## Runtime: the `app` object

Every component gets the same `app`:

| Member | Meaning |
|---|---|
| `app.spec` | resolved spec (title, store, endpoint, relay, theme, layout, components with options) |
| `app.cfg` | dataset config from `browserConfig` (title, source, store_url, endpoint, variables, dims, crs, bbox, attrs, global…). **Never null**: before the store is loaded and for a blank viewer it is `blankConfig()` (no variables, global EPSG:4326 world) |
| `app.blank` | true while there is no store (blank viewer or the store failed: then `app.startupError` is set) |
| `app.params` | `URLSearchParams` of the page as loaded |
| `app.varOf(name)` | the variable config of `name` |
| `app.state` | `{selected: [] (bottom-first), hidden: Set, dims: {}, roles: {}, opacity: {}, centerLon, map, labelMode, basemap}` |
| `app.bus` | event bus (events below) |
| `app.storage` | `get(key)`, `set(key, value)`, `remove(key)`; keys auto-prefixed `gv:`, in-memory fallback |
| `app.url` | `register(key, {read(params), write(params)})`, `sync()` (debounced `history.replaceState`), `read()` (called once by the app after the config loaded); entries run in registration order, the core's first |
| `app.style` | `get(name)` (copy of `{cmap, reversed, vmin, vmax, log?}`), `set(name, patch, {explicit = true, persist = true})` → returns false for an invalid range/colourmap, else emits `style:changed` and syncs the URL (`explicit: false` = the automatic Auto of D-53: not marked, not stored), `reset(name)`, `isExplicit(name)`, `colorExpr(name)`, `stopsOf(style)`, `cmaps`, `groups`, `ramp`, `cmapLabel`, `listedGroups(current)` (groups to list given the shown sources, D-42), `sources` + `setSourceShown(source, on)` (emits `cmaps:changed`; the last source cannot be switched off, D-47), `gradientCss`, `effectiveLog`, `niceTicks`, `niceLogTicks` |
| `app.layers` | `select(name, before?)` (`before` = the selected variable it goes in front of in the top-first list; omitted = on top; `null` = bottom), `deselect(name)`, `move(name, before)`, `setVisible(name, on)`, `setDim(dim, i)`, `setOpacity(name, x)`, `setBasemap(id)`, `setCenterLon(lon)` (reloads the page, as the reference); `basemaps` (`[[id, label]]`), `group(name)` (`{layers, sources}` of a visible variable), `unionDims()`, `opacityOf(name)`, `start()` (internal: creates the map) |
| `app.frame` | `values(name)` (Float64Array of the current frame), `extent(name, positive)`, `sample(coordinate)` → `[{name, value}]` top-most first, `autoStyle(name, {auto})` and `minMaxStyle(name)` (compute the range from the loaded tiles and apply it through `app.style`; false when nothing is loaded) |
| `app.geo` | `lonLat(coord)` → `[lon, lat]` or null, `inExtent(coord)` (view-projection coordinates, world copies handled) |
| `app.label(v)` | label of a variable (object or name; array name or long name per `app.state.labelMode`); `app.setLabelMode(mode)` emits `labels:changed` |
| `app.openStore(src, endpoint)` | validate a store and reload the page on it |
| `app.slot(name)` | the slot element |
| `window.gvApp` | the same object, for debugging |

Components never touch another component's DOM. They talk through `app.layers`/`app.style` (which emit events)
and the bus.

### Events

`config:loaded(cfg)` (also for a blank viewer: `cfg.variables` is empty), `map:ready(map)` (always after
`config:loaded`), `selection:changed(selected)`, `visibility:changed(name)`, `style:changed(name)`,
`dims:changed({dim, index})`, `opacity:changed(name)`, `roles:changed(roles)`, `labels:changed(mode)`,
`basemap:changed(id)`, `cmaps:changed(sources)`, `centerlon:changed(lon)`, `layer:rendered(name)` (the map finished a
render with that variable on it; fires on every `rendercomplete`), `card:settings({name, el})` (variable-cards offers a
settings container; style components fill it), `error(err)` (shown as a toast; `err.hint` is printed under the message).
`varinfo:open({name, anchor})` (a component asks for the attributes popover of a variable, `anchor` = the element it
sits next to; var-attrs listens), `varinfo:state({name|null})` (var-attrs announces which variable's popover is open, null =
closed, so the opener can mark its button), `timeline:step(n)` (a component asks the timeline to move its dimension by `n` steps, e.g. the sliders' arrow
keys; the timeline listens, stops playback and steps).
Only the core emits the first group up to `centerlon:changed` and `layer:rendered`; `roles:changed`, `card:settings`,
`varinfo:*`, `timeline:step` and `error` are free for components. Components are initialised **before** the store is loaded, so they subscribe to
`config:loaded` / `map:ready` instead of reading `app.cfg` in `init`.

## Component contract

```js
registerComponent({
  name: 'readout',
  init(app, root, opts) { /* build DOM inside root, subscribe to events */ },
});
```

`root` is a `<div class="gv-<name>" data-gv-component="<name>">` that the assembler places in the component's slot.
`opts` = manifest defaults merged with the spec's options (already merged in the embedded spec). A component can be
used once per page. The assembler wraps each `component.js` in a block, so its top-level helpers are private to it;
core functions (`h`, `fmt`, `unitsOf`, `ICON`, …) are visible to it.

`manifest.json`:

```json
{
  "name": "readout",
  "description": "Pointer value of each visible variable plus lat/lon",
  "slots": ["overlay-bl", "overlay-br", "overlay-tl", "overlay-tr", "bottom", "sidebar"],
  "default_slot": "overlay-br",
  "requires": [],
  "conflicts": [],
  "options": {"latlon": {"type": "bool", "default": true, "doc": "show lat/lon line"}}
}
```

Option types: `bool`, `int`, `number` (optional `min`/`max`), `string`, `enum` (needs `choices`); every option needs a
`default` of its type. The assembler checks manifests too (slots in the fixed list, `default_slot` among `slots`).

`option_requires` (optional) maps an option to `{value: [components]}`: with that option value the listed components must
be in the spec. Unlike `requires` they are **not** added automatically; the assembler stops with an error (exit 2), e.g.
`"option_requires": {"placement": {"card": ["variable-cards"]}}` on `legend` and `style-controls`.

`requires` are other components that must be present (the assembler adds them, logging it); `conflicts` must
not be present together (e.g. `variable-cards` and `variable-dropdown`, both own the selection UI).

## Components

`python3 scripts/assemble.py --list` (or `--list --json`) is the source of truth for slots, options, requires and
conflicts. Short overview:

| Component | Default slot | Role | Requires / conflicts |
|---|---|---|---|
| variable-cards | sidebar | stacked variable cards (selection, order, opacity, settings container) | conflicts variable-dropdown |
| variable-dropdown | topbar | select one or several variables | conflicts variable-cards |
| style-controls | sidebar | colourmap, range, Auto / Min/Max, opacity; `placement` card or panel | `placement = card` needs variable-cards |
| legend | overlay-bl | colourbar; `placement` overlay or card | `placement = card` needs variable-cards |
| var-attrs | overlay-tl | attributes popover of a variable (`varinfo:open`) | |
| timeline | bottom | time axis with play and keys | |
| dim-sliders | overlay-br | one slider per non-Horizontal dimension | |
| dim-roles | sidebar | assign dimensions to Horizontal / slider roles | |
| readout | overlay-br | pointer values and lat/lon | |
| basemap | overlay-tl | basemap selector | |
| info-panel | topbar | store and dataset information | |
| store-picker | topbar | open another store | |
| label-mode | sidebar | variable label: array name or long name | |
| cmap-sources | sidebar | which colourmap sources are listed | |
| center-lon | sidebar | centre longitude of the map | |

Every component that can sit in `sidebar` (except `variable-cards`) can also sit in `sidebar-bottom`; the global-settings
components (label-mode, basemap, dim-roles, cmap-sources, center-lon) go there in `presets/full.toml`, in one group.

## Slots (fixed)

```
┌──────────────────── topbar ────────────────────┐
│ sidebar │ overlay-tl            overlay-tr │ (sidebar on the right
│ (scrolls│                                   │  when layout.sidebar = "right")
│  )      │              map                  │
│─────────│ overlay-bl            overlay-br │
│sidebar- ├──────────── bottom ───────────────┤
│ bottom  │                                   │
└─────────┴───────────────────────────────────┘
```

`topbar`, `sidebar`, `sidebar-bottom`, `bottom`, `overlay-tl`, `overlay-tr`, `overlay-bl`, `overlay-br`. Slots without a visible child take no space and draw no chrome
(`.gv-slot:empty` and `.gv-slot:not(:has(> :not([hidden])))` in `core/layout.css`: a component may `hidden` its root; the
assembler emits no whitespace in slots). The sidebar `<aside>` exists only when a component sits in it, otherwise
`data-sidebar="none"`; when all its components are hidden the CSS drops the column too. The right-hand overlays leave room for the OL zoom (top right) and attribution
(bottom right) controls. The `topbar` and `bottom` slots are rows, the `sidebar` slot a column. `sidebar-bottom` is a
second column slot inside the sidebar `<aside>`, pinned under the scrolling `sidebar` slot (always visible, own scroll
beyond `max-height: 45%`, hidden when empty); the `<aside>` exists when either slot has a component.
Several components in one slot stack in spec order. Layout options: `sidebar = "left" | "right"`,
`sidebar_width` (px, 120-900), `sidebar_collapsible` (bool, default true; the collapse toggle and the vertical title
shown when collapsed belong to the core), `theme = "auto" | "light" | "dark"` (a top-level key; `data-theme` on `<html>`,
auto follows `prefers-color-scheme`).

## Spec (TOML)

```toml
title = "MUR SST"
store = "s3://spi-greenfjord-public/test/mur_sst_subset.zarr"   # optional default store
endpoint = "https://os.zhdk.cloud.switch.ch"
relay = ""                     # URL prefix put in front of cross-origin store URLs, e.g. "/proxy/" with scripts/serve.py
theme = "auto"

[layout]
sidebar = "left"
sidebar_width = 320
sidebar_collapsible = true

[[components]]
name = "variable-cards"
slot = "sidebar"

[[components]]
name = "readout"
slot = "overlay-br"
options = { latlon = false }
```

### Groups

A component entry may carry `group = "Name"`. Consecutive components in the same slot with the same group name are wrapped
by the assembler in one collapsible `<section class="gv-group">`: a header button (gear icon, title, chevron;
`aria-expanded`, `aria-controls`, built by `initGroups` in `core/app.js`) and a body. Groups work in any slot. The
collapse state is kept in `app.storage` under `group:<name>`; absent that, the optional top-level table decides:

```toml
[groups."Global settings"]
collapsed = true      # initial state (default false = expanded)
icon = "gear"         # "gear" (default) | "none"

[[components]]
name = "label-mode"
slot = "sidebar-bottom"
group = "Global settings"

[[components]]
name = "basemap"
slot = "sidebar-bottom"
group = "Global settings"
```

Using one group name non-consecutively in the same slot is an error (exit 2); the same name in different slots gives
independent sections that share the stored state. A group whose components are all `hidden` hides itself (CSS, like
slots). The resolved spec carries `components[].group` and `groups` (defaults filled in for used groups).

`?store=…&endpoint=…` in the page URL wins over the spec's `store`/`endpoint`; `?store=` (empty) gives the blank viewer.

`assemble.py SPEC -o OUT.html` validates (unknown top-level/layout keys, unknown component, duplicate component, slot not
allowed, unknown option, wrong option type, conflicts, bad `groups` table, non-consecutive groups), resolves `requires` (the required component is inserted in front
of the one that needs it, with a `note:` on stderr), and writes the page. Errors are printed as `error: …` (all of them),
exit code 2. `assemble.py --list` prints every component with its slots and options (`--json` for a machine-readable
form); `--components DIR` points at another component library.

## Rules for component authors

- Port logic from the reference function by function; keep its behaviour unless the component's options say
  otherwise. Cite the reference function names in a short comment.
- No globals shared between components; everything through `app`.
- CSS only under `.gv-<name>`, colours only via the tokens in `theme.css`.
- Pure functions (maths, parsing, ticks) are top-level in `component.js` so `test.cjs` can extract and run them
  with `node:vm`, the way the reference's `tests/preview_*.cjs` do.
